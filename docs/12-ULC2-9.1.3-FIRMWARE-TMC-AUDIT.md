## Runtime and map assets

The 9.1.3 navigation executable is:

```text
Storage Card4/NNG/nngnavi.exe
PE32 Windows CE MIPS R4000, 6 sections
SHA-256 c1844209f3b470a2741c36efc95222fdc22092e2b402c721e3fe6fd58535fb34
```

The firmware contains a larger NNG runtime, `data.zip`, `global_cfg.zip`, and
a dedicated `ux/tmc.zip` UI package. It contains no national map/location data:

```text
*.fbl, *.fpa, *.fda, *.fds, *.ftr, *.hnr, *.poi, *.tmc: 0
content/map/: 0 files
points/roads/offsets/LCL/location-dataset files: 0
```

The runtime contains generic extension strings `*.fbl`, `*.fpa`, `*.hnr`, and
`*.tmc`, but no hard-coded FBL path or location-table filename. Thus it knows
how to operate on externally supplied map files, but this firmware does not
ship the LCD-to-road table.

## UK INRIX relevance

This is more useful than 4.1.0 for the current UK research because its bundled
`config/tmc_cc_ecc_sid_ltn.csv` contains:

```text
GBR; ECC=E1; CC=C; LTN=10; SID=10; INRIX; Pay TMC; licence aliases 1:266
GBR; ECC=E1; CC=C; LTN=10; SID=11; INRIX-LONDON
GBR; ECC=E1; CC=C; LTN=7;  SID=7;  Trafficmaster
```

The first row matches the current head-unit service family:

```text
CC=12 decimal (C hex), ECC=E1, LTN=10, SID=10, provider INRIX
```

This is provider/service-selection metadata, not the location list. It does
not establish that an old 9.1.3 map's LTN-10 associations equal the current
2026 UK OSM map's associations.

## TMC resources

`data.zip` includes event/UI resources such as `tmccategory.dat`,
`tmceventlist.csv`, `tmcevents*.{bin,dat}`, `traffic_codeconfig.*`, and
`traffic_phrases.bin`. The dedicated `ux/tmc.zip` contains only TMC UI scripts,
styles and states (for example `tmc.lua`, `tmc_scripts.lua`, and
`traffic_current_location` presentation fields). Neither is a national
location-code list.

## Ghidra reference status

The 9.1.3 MIPS runtime was analysed headlessly with Ghidra 11.4.2 in:

```text
TrafficReport/tmp/ghidra-ulc2-913-runtime/
TrafficReport/tmp/ghidra-ulc2-913-runtime.log
TrafficReport/tmp/ghidra-ulc2-913-unicode-maprefs.log
```

It resolves TMC-cache and LTN-debug callers, but unlike 4.1.0 has no direct
Unicode `map\\basemap.fbl` reference. The map path is constructed indirectly.
This makes it the more relevant binary to continue analysing once a matching
9.1.3/current map container is available. Subsequent analysis did recover the
map-resident TMC descriptor/index decoder; see
`13-ULC2-TMC-FBL-DECODER.md`.

## Conclusion

The version correction is confirmed and the requested ULC2 9.1.3 image has
been successfully extracted. It adds an **INRIX LTN-10 capable NNG runtime**
reference, not the missing national table. The table must still be associated
with separately distributed UK map media; the strongest remaining path is the
actual current Linux navigation runtime working against the current
`UnitedKingdom_osm.fbl`.
